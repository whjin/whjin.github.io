操作系统跨进程通信（IPC）

进程与线程基础

在深入 IPC 之前，先厘清两个基础概念：

  • 进程：操作系统资源分配的基本单位，拥有独立的地址空间、文件描述符与资源。进程间默认是相互隔离的，一个进程无法直接访问另一个进程的内存。
  • 线程：进程内部执行任务的基本单位，同一进程内的线程共享地址空间与资源，可以通过共享内存直接通信。

正是因为进程之间地址空间相互隔离，才需要一套"跨进程通信"的机制（IPC，Inter-Process Communication）来完成数据交换与协作。

为什么需要 IPC

在实际系统中，多个进程协作的场景非常普遍：

  • 后端服务拆分后，各进程需要传递任务与结果。
  • 客户端与服务端（前后端）通过网络接口通信。
  • 父进程需要把数据、信号传递给子进程。
  • 多个进程同时访问共享资源时需要进行同步。

IPC 要解决的核心问题有两个：一是数据传输（如何在进程间传递信息），二是同步与互斥（如何保证并发访问的一致与安全）。

管道（Pipe）

管道是最古老、最简单的 IPC 方式，本质是内核提供的一块缓冲区，进程通过读写文件描述符来传递数据。

特点：

  • 单向数据流：数据从写端流向读端，一个方向。
  • 适合父子进程或有亲缘关系的进程间通信。
  • 匿名管道只能用于亲缘进程；命名管道（FIFO）可用于无亲缘关系的进程。
// 匿名管道示例（C）
int fd[2];
pipe(fd);          // fd[0] 读端，fd[1] 写端
if (fork() == 0) {
  // 子进程：关闭读端，写数据
  close(fd[0]);
  write(fd[1], "hello", 6);
} else {
  // 父进程：关闭写端，读数据
  close(fd[1]);
  read(fd[0], buf, sizeof(buf));
}

适用场景：Shell 管道（cmd1 | cmd2）、父子进程间传递流式数据。缺点是单向、无格式、不适合大数据量随机访问。

消息队列

消息队列以"消息"为单位在进程间传递数据，发送方与接收方解耦。

特点：

  • 进程间以消息为单位收发数据，天然带边界与类型。
  • 解耦发送与接收：发送方不必等待接收方，消息由内核队列缓存。
  • 支持多对多通信，比管道更灵活。
// 发送消息（POSIX 消息队列示例）
mqd_t mq = mq_open("/myqueue", O_CREAT | O_WRONLY, 0644, &attr);
mq_send(mq, "data", 4, 0);

适用场景：需要异步、松耦合、带优先级的进程通信，如任务队列。缺点是消息有大小限制，性能低于共享内存。

共享内存

共享内存是速度最快的 IPC 方式，因为它让多个进程映射同一块内存区域，数据写入后其他进程立即可见，无需经过内核拷贝。

特点：

  • 速度快，接近直接内存访问。
  • 但多个进程同时读写时需要配合同步机制（如信号量、互斥锁）保证数据一致性。
// 映射共享内存（System V 示例）
int shmid = shmget(IPC_PRIVATE, 4096, IPC_CREAT | 0666);
char *addr = shmat(shmid, NULL, 0);
strcpy(addr, "hello");   // 写入共享区，其他进程立即可读

适用场景：大数据量、高频读写，如进程间共享配置、图像帧、日志缓冲区。是高性能系统的首选。

信号量（Semaphore）

信号量本身不传递数据，而是用于进程间同步与互斥，解决共享资源并发访问的问题。

特点：

  • 计数型同步原语，控制同时访问资源的进程数量。
  • 配合共享内存使用，保证读写安全。
// 信号量 P/V 操作示意
sem_wait(&sem);   // P：申请资源，资源不足则阻塞
// ... 访问共享资源 ...
sem_post(&sem);   // V：释放资源

适用场景：生产者-消费者模型、多进程保护临界区、限制并发连接数。

信号（Signal）

信号用于异步通知进程某个事件发生，是一种轻量级的进程间通知机制。

特点：

  • 只能传递事件通知，不携带数据。
  • 用于通知进程"某件事发生了"，如终止、挂起、闹钟到期。
signal(SIGINT, handler);   // 注册处理函数
kill(pid, SIGTERM);        // 向进程发送终止信号

适用场景：进程终止、异常处理、心跳监控。因为不携带数据，不适合业务数据传递。

Socket

Socket 是跨网络的 IPC 方式，支持本机进程之间（Unix Domain Socket）以及远程主机之间的通信，是网络应用的基础。

特点：

  • 可跨网络通信，支持 TCP/UDP。
  • 本机使用 Unix Domain Socket 时，性能远高于 TCP，且无网络开销。
  • 后端服务器与前端/客户端之间的大量交互，本质都是 Socket。
# Python TCP Server 示意
import socket
s = socket.socket()
s.bind(('0.0.0.0', 8000))
s.listen(5)
while True:
    conn, addr = s.accept()
    conn.send(b'hello')
    conn.close()

适用场景：分布式系统、前后端服务、跨主机微服务通信。是应用最广泛的 IPC 方式。

IPC 方式对比与选型

方式 数据量 速度 复杂度 是否跨机 典型用途
管道 小 中 低 否 父子进程流式数据
消息队列 中 中 中 否 异步解耦、任务队列
共享内存 大 高 高（需同步） 否 高频大数据共享
信号量 无数据 - 中 否 同步与互斥
信号 无数据 高 低 否 事件通知、异常
Socket 大 中 中 是 网络与分布式通信

选型建议：

  • 单机内、性能优先 → 共享内存 + 信号量。
  • 单机内、简单可靠 → 管道或消息队列。
  • 跨主机 / 前后端 → Socket（TCP/Unix Domain Socket）。
  • 只需通知事件 → 信号。

理解各种 IPC 的原理与取舍，是写出稳定、高性能多进程与分布式系统的关键能力。根据数据量、性能需求与是否跨机，选择最合适的通信方式，才能做到既高效又可控。
