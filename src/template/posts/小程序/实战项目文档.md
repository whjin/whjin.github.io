做小程序输入框时，你可能遇到过一个诡异的问题：用搜狗输入法打中文时，`input` 事件拿到的值和用户实际看到的不一样。这篇文章讲清楚原因和解决方法。

## 问题现象

在手机端使用搜狗输入法的英文预测模式或中文拼音模式时：

- 用户输入 `nihao`，输入法候选栏显示"你好"
- 但 `input` 事件回调里拿到的值可能是空的或不完整的
- 因为输入法在"组词"阶段，字符还没有确认，浏览器/小程序框架不触发 `input` 事件

这就是 **composition（文本合成）** 问题——输入法在组词过程中，文本处于"未确认"状态。

## 解决方案：ignoreCompositionEvent

uniapp 的 `input` 组件有一个 `ignoreCompositionEvent` 属性：

```html
<input
  v-model="keyword"
  :ignoreCompositionEvent="false"
  @compositionstart="onCompositionStart"
  @compositionend="onCompositionEnd"
  @compositionupdate="onCompositionUpdate"
/>
```

**设为 `false` 时**，在文本合成期间会触发以下事件：

| 事件 | 触发时机 |
|------|---------|
| `compositionstart` | 输入法开始组词（如按下第一个拼音字母） |
| `compositionupdate` | 组词过程中每输入一个字符 |
| `compositionend` | 组词结束，用户选中候选词，文本确认 |

## 正确监听输入值

如果你需要在输入法组词过程中实时拿到值（比如搜索联想），需要同时监听 `input` 和 composition 事件：

```js
export default {
  data() {
    return {
      keyword: '',
      isComposing: false
    };
  },
  methods: {
    onCompositionStart() {
      this.isComposing = true;
    },
    onCompositionUpdate(e) {
      // 组词过程中实时拿到当前拼音
      console.log('正在输入：', e.detail.value);
    },
    onCompositionEnd(e) {
      this.isComposing = false;
      // 组词结束，拿到最终确认的文本
      this.keyword = e.detail.value;
      this.search();
    },
    onInput(e) {
      // 非组词阶段（英文、数字）直接更新
      if (!this.isComposing) {
        this.keyword = e.detail.value;
      }
    }
  }
}
```

## 什么时候需要处理

| 场景 | 需要处理吗 |
|------|-----------|
| 普通表单输入框 | 不需要，默认行为就行 |
| 搜索联想 / 实时搜索 | 需要，否则组词阶段没有联想结果 |
| 聊天输入框 | 一般不需要 |
| 验证码输入 | 不需要 |

**总结**：默认 `ignoreCompositionEvent` 为 `true`（忽略 composition 事件），这是大多数场景的正确行为。只有需要在输入法组词阶段实时拿到值时，才设为 `false` 并处理 composition 事件。
