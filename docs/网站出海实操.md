## 一、总览：一次完整的出海闭环

```
海外网站开发 → SEO 静态化(爬虫收录) → Google Search Console(提交/验证)
→ Google AdSense(审核就绪) → 付费订阅(变现) → 审计迭代
```

**wuhuajin.com 实战路径（时间线）：**

1. **静态站搭建**：GitHub Pages 纯静态站，Markdown 文章 + JS 渲染详情页。
2. **国际化**：默认英文界面，点 lang 图标切中文（单代码、JSON 字典，不做双语双套页）。
3. **合规页**：Privacy / Terms / About / Contact / 404 五页 + ads.txt + robots.txt + sitemap。
4. **SEO 静态化**：42 篇 md 预渲染为独立 `.html`，解决"爬虫看不到 JS 渲染内容"的收录缺口。
5. **目录整理**：静态页归入 `posts/<分类>/html/`，md 留在分类根目录。
6. **AdSense 就绪**：meta description 全量补全、JSON-LD 结构化、Consent Mode v2（GDPR）。
7. **付费订阅**：Ko-fi（关联 PayPal）+ 会员档，免费+付费会员模式。
8. **审计迭代**：四维审计 + 5 项缺陷修复，全部通过。
9. **上线后缺陷修复**：弹窗层级 / 资源页空白 / 回到顶部定位 / 横向滚动 / URL 统一，全部实测通过。
10. **访问统计**：Cloudflare Web Analytics（beacon 国内外同一后台）+ Cloudflare Worker 代理显示 footer 浏览量；后升级为 **Worker + D1 自维护计数器** 统计「建站以来全部累计」（httpRequests1dGroups 只能查近 1 年，见第十章 10.6）。
11. **搜索去重**：修复首页/搜索出现重复卡片——同一文章在多分组（「我的」+文章分组）各存一条，feed 渲染结果按「标题+分类」去重，优先保留静态页链接（见踩坑 #20）。

**核心结论**：一个静态站要过 Google 收录 + AdSense 审核，**内容可被爬虫读到 + 合规 + 结构化 + 隐私合规**是四条主线；**上线不等于结束**，上线后仍有滚动、层级、URL 等移动端/交互缺陷，需按"实测 → 定位 → 修复 → 复验"闭环补完。

## 二、海外网站开发要点

### 2.1 技术选型：GitHub Pages 静态站

| 维度 | 说明                                                  |
| ---- | ----------------------------------------------------- |
| 托管 | GitHub Pages 免费、全球 CDN、HTTPS 默认，海外访问友好 |
| 内容 | Markdown 源文 + 构建脚本预渲染为静态 HTML             |
| 域名 | 绑定独立域名 `wuhuajin.com`，主域唯一                 |
| 收益 | 无服务器成本、无需运维、利于爬虫                      |

### 2.2 国际化 i18n

- **单代码运行时方案**：JSON 字典（`zh.json`/`en.json`），不做双语双套页。
- **默认英文、点击切换中文**：默认展示英文面向海外，用户点语言图标切换。
- **交互**：右上角语言图标（`lang.png`），选择存 `localStorage`。
- **海外语言切换图标**：用 Google / 系统标准的 Language 图标风格，满足海外用户认知，避免自造图形。

### 2.3 移动端 / 响应式

- 卡片布局自适应：单行 ≤4 个卡片，屏宽压缩到最小宽度(300px)时自动换行。
- 底部/顶部边距一致（外层留白均衡），手机端/平板同样适配。
- 回到顶部按钮保留，`bottom` 定位避让（如 66px）。
- **横向滚动控制**：窄屏/移动端外层不产生横向滚动条。`html.home-page` 用 `overflow-x: hidden; overflow-y: auto`（整页滚动保留纵向）；横向溢出根因常是广告容器，给 `ins.adsbygoogle { max-width: 100% }` 从源头消除。
- **移动端缩放**：viewport 用 `width=device-width, initial-scale=1.0`，**不要**加 `user-scalable=no`（否则禁用双指/三指缩放）。去掉后桌面不受影响、移动端可缩放。

### 2.4 目录结构规范（重点）

```
src/template/posts/<分类>/
├── <标题>.md                    # md 源文（人维护）
└── html/
    └── <标题>.html              # 预渲染静态页（脚本生成）
```

- **规则**：分类根目录只放 md；静态 html 一律进 `html/` 子目录。
- **菜单模板页例外**：`文章/article.html`、`教程/tutorial.html`、`友链/link.html`、`工具/tool.html`、`资源/resource.html` 这类非文章页留在根目录。
- **好处**：目录清晰、SEO URL 规整、md 与 html 不混淆。

### 2.5 变现：付费订阅（免费+付费会员）

- **方案**：Ko-fi 会员（Memberships）关联 PayPal 收款。
- **模式**：免费内容 + 付费会员专区（member-only posts），非邮件/RSS 订阅。
- **档位**：可设多档（如 月付/年付），勾选"允许专属帖"让会员档有内容权限。
- **注意**：PayPal 商户行业分类编码若选"数字商品/媒体/书籍、电影、音乐"，**不支持使用中国跨境人民币收付款服务**——需确认收款方式可用。
- **集成**：首页卡片"Support 支持/订阅"卡，默认英文、点语言切中文，文案 `Enjoy my content? Become a member to unlock exclusive articles...`，按钮 `Become a Member / 成为会员`，链接到 Ko-fi。

### 2.6 卡片式信息架构（SEO 友好）

- 首页/资源页用卡片组织（订阅卡、广告位卡、Popular tags、分类、文章流）。
- 广告位卡：未配置时显示"虚位以待 / Advertisement"占位，不影响布局。
- 卡片结构统一：主标题 + 图标/头像 + 主题信息 + ul 列表 + CTA 按钮。

### 2.7 弹窗 / 浮层层级体系（用户锁定"导航始终置顶"）

上线后出现"弹窗盖住顶部导航栏""全屏预览被弹窗盖住"两类层级问题，最终锁定一套 z-index 体系：

```
banner(广告) 30  >  header(搜索框) 29  ≥  fullscreen(全屏预览) 29  >  modal(弹窗) 28  >  footer 27
```

- **弹窗必须低于顶部导航栏**：导航栏（banner + 搜索框所在 header）始终置顶可见。
- **全屏预览必须高于弹窗**：否则点二维码全屏时弹窗盖住大图；全屏预览仍低于 banner。
- 改层级用 computed z-index 实测复核，别只信 CSS 写法（可能被其他规则覆盖）。

## 三、SEO 与爬虫优化（核心）

### 3.1 为什么要静态化

**痛点**：JS 渲染的单页（viewer）内容由 JS 异步填充，Google 爬虫首次抓取常看到空容器 → 内容不被收录。

**解决**：把每篇 md 在构建时**预渲染为独立 `.html`**，正文内联进页面，爬虫直接读到完整内容。

### 3.2 静态化方案（三层结构）

每个静态页同时具备三套能力：

| 层         | 实现                                                         | 作用                                  |
| ---------- | ------------------------------------------------------------ | ------------------------------------- |
| 预渲染正文 | `<noscript>` 内放完整渲染后的 HTML                           | 爬虫 / 无 JS 环境读到内容（SEO 保真） |
| 运行时渲染 | JS 从相邻 `../<标题>.md` 用 marked 渲染                      | **改 md 刷新即更新**，内容实时同步    |
| 抗注入滚动 | MutationObserver 检测 style 被改写 auto 则用 JS 视口高度重施 | 防止预览环境把滚动容器撑开、滚不到底  |

> 关键：`#markdown-content` 初始为空，由运行时渲染填充；预渲染正文放 `<noscript>` 既保 SEO 又不污染可见正文（避免"把 description 渲染进正文"的 bug）。

### 3.3 URL 结构与重定向

- 文章 URL：`/src/template/posts/<分类>/html/<标题>.html`
- **旧 URL 兼容**：viewer 链接保留不 404；但改版后旧文章 URL 会 404，需在 Search Console 提交新 sitemap 让 Google 重新抓取。
- 目录/菜单页仍走 `/viewer.html?path=xxx`（这些是动态列表页，非独立文章，SEO 价值低，**无需静态化**）。
- **统一命名**：`/view` 统一改为 `/viewer.html`；server.js 用 `ALIASES = { '/viewer': '/viewer.html' }`，**移除 `/view` 旧别名**，单一入口便于维护，避免旧链接残留导致 404/重复。
- **`.nojekyll`**：GitHub Pages 默认启用 Jekyll，会吞掉无 front-matter 的 md 文件导致 404；仓库根建空 `.nojekyll` 禁用，保证 md/静态页原样发布。
- **首页本体**：`home.html` 移至仓库根，并加 `<meta name="robots" content="noindex">`（避免首页重复 + 主体空白事故）；服务器不设置首页 301 重定向。

### 3.4 canonical / OG / JSON-LD

每篇静态页必备：

- `<link rel="canonical">` 指向自身绝对 URL
- `og:title` / `og:description` / `og:url` / `og:image` / `og:locale`
- `twitter:card` / `title` / `description`
- `<script type="application/ld+json">`：`Article` 结构化数据（headline/description/author/publisher/datePublished/inLanguage/mainEntityOfPage）

首页必备：

- JSON-LD `@graph`：`Person` + `WebSite`（name/alternateName/jobTitle/email/sameAs/inLanguage/publisher）
- `<meta name="google-adsense-account">`

### 3.5 robots.txt / sitemap.xml / ads.txt

- `robots.txt`：`User-agent: *` + `Allow: /` + `Sitemap: https://域名/sitemap.xml`
- `sitemap.xml`：基础页(5) + 全部文章(42)，URL 与 feed 严格同步
- `ads.txt`：`google.com, pub-XXXXXXXX, DIRECT, f08c47fec0942fa0`

### 3.6 meta description 完整策略

- **不让任何条目 description 为空**：让 Google 能快速提取站点信息，提高审核效率与通过率，也方便爬虫。
- 来源优先级：优先从对应 md 文档提取 150-300 字摘要；无 md 的条目（外部工具/推荐卡）用产品一句话定位。
- 首页/站点的 description 写清楚定位（个人主页/技术博客 + 核心技术栈 + 内容类型）。

### 3.7 搜索与筛选（站内 SEO/体验）

- **相关度排序**：标题命中(3) > 分类/标签命中(2) > 仅描述命中(1)，同分保序。
- **三向重置**：搜索 / 分类 / 标签 交替切换时，先重置前一个操作再应用新的（避免叠加）。
- **结果去重**：feed 渲染结果按「标题+分类」去重，同一文章在多分组只显示一次，优先保留静态页链接（`feed/index.js` `filtered()` 末尾）。

### 3.8 上线后 URL/收录专项

- **部署后二级页 404**：先查 feed 生成的 URL 是否含 `/html/` 段、server 别名是否统一；再确认 `.nojekyll` 存在。
- **URL 信任度**：避免在链接 URL 上追加 `_gl` 等追踪参数（GA4 `url_passthrough` 会追加，导致链接丑陋、用户不信任）——已通过 `ads_data_redaction` 与不启用 `url_passthrough` 规避。

## 四、Google Search Console 实操

### 4.1 首次提交

1. 站点提交（域名属性）→ 验证所有权（DNS/HTML 标签等）。
2. 提交 `sitemap.xml`。
3. 用"网址检查"验证首页与代表文章能被抓取。

### 4.2 改版后 URL 变更处理

- 文章 URL 从 `posts/<分类>/<标题>.html` → `posts/<分类>/html/<标题>.html`。
- **旧 URL 会 404**：提交新 sitemap，等 Google 重新抓取；若旧 URL 已被索引，考虑 301 或让其自然淘汰。
- 工作流：**本地改完 → 提交 GitHub 部署 → 再处理 Search Console**（重新提交 sitemap / 请求编入索引）。

### 4.3 爬虫验证

- 用"网址检查 → 测试实际 URL"，看 Google 渲染的页面是否含正文（验证静态化是否生效）。
- 检查 robots.txt 可访问、sitemap 无 404。

## 五、Google AdSense 审核要点

### 5.1 合规页（5 页必备，可访问、从页脚可点）

| 页面    | 关键内容                                                                             |
| ------- | ------------------------------------------------------------------------------------ |
| Privacy | 收集数据、广告 Cookie（含 Google/DART cookie）、第三方、数据保留、用户权利、联系方式 |
| Terms   | 服务范围、许可、免责、知识产权、责任限制、法律                                       |
| About   | 站主、技术栈、内容定位                                                               |
| Contact | 真实可用邮箱、GitHub、社交                                                           |
| 404     | 友好提示 + noindex                                                                   |

> 全站页脚四个法律链接一致；合规页 `index, follow`（404 例外）。

### 5.2 Consent Mode v2（GDPR 合规，必做）

在 `<head>` 中、加载 gtag **之前**：

```html
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag() {
    dataLayer.push(arguments);
  }
  gtag('consent', 'default', {
    ad_storage: 'denied',
    ad_user_data: 'denied',
    ad_personalization: 'denied',
    analytics_storage: 'denied',
  });
  gtag('set', 'ads_data_redaction', true);
  gtag('set', 'url_passthrough', true);
</script>
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXX"></script>
```

- 默认拒绝，由 cookie banner 用户选择后更新为 granted/denied。
- 再加载 adsbygoogle 与 amp-auto-ads。
- **注意**：`url_passthrough: true` 会让 GA4 在链接 URL 追加 `_gl` 追踪参数（链接变丑、降低信任）。海外站可关闭（`ads_data_redaction` 已能脱敏），保 URL 美观。

### 5.3 内容与收录

- 内容原创、充分、可被爬虫读取（静态化）。
- meta description 全量补齐（见 3.6）。
- JSON-LD 结构化数据完整。

### 5.4 审核期隐藏国内元素

- 打赏码、微信二维码、国内音乐播放器等用 `show: false` 数据字段隐藏（代码保留、部署剥离可选）。
- 海外社交为主：GitHub、X/Twitter。

### 5.5 收款行业分类注意

- PayPal 商户行业分类编码若选"数字商品/媒体/书籍、电影、音乐"，**不支持使用中国跨境人民币收付款服务**——选分类前先确认收款通道支持范围，避免审核/收款受阻。

## 六、审计方法论（四维审计）

每次改造后按四维审计，**全部通过才算可交付**：

| 维度               | 检查内容                                                       |
| ------------------ | -------------------------------------------------------------- |
| ① 目录结构与一致性 | posts/html/ 结构、feed/sitemap URL 全含 `/html/`、构建脚本幂等 |
| ② 功能缺陷修复     | 搜索相关度、描述注入、筛选重置、滚动、md 实时刷新              |
| ③ SEO/AdSense 就绪 | meta/JSON-LD/Consent v2/gtag/adsbygoogle/robots/sitemap        |
| ④ 冗余与一致性     | 无残留旧引用、scripts 干净、viewer 分支路径正确、无临时文件    |

**验证方法**：

- **幂等构建**：重跑 `build-articles.cjs`（42/42、feed 0 更新）、`build-sitemap.cjs`（47 条）。
- **浏览器实测**：新路径页面渲染 + 滚动（5/5 可滚到底）、搜索/筛选三向重置、卡片 href 指向 `/html/`。
- **结构核验**：用 node 脚本统计 feed 空 description、旧 URL 残留、菜单页保留。
- **上线后复测**：用浏览器实测 z-index 层级、回到顶部定位、横向滚动、移动端缩放，改一处即按"定位 → 修复 → 复验"闭环。

## 七、典型踩坑与解决方案（Lessons Learned）

| #   | 踩坑           | 症状                           | 解决                                                                       |
| --- | -------------- | ------------------------------ | -------------------------------------------------------------------------- |
| 1   | 滚动问题       | 静态文章页滚动到底部卡住       | 去掉内联高度 + MutationObserver 抗注入 + `window.innerHeight` 像素高度重施 |
| 2   | 搜索不准确     | 输"node"返回大量仅描述命中     | 相关度排序（标题>标签>描述）                                               |
| 3   | 描述注入       | md 的 description 被渲染进正文 | 预渲染正文放 `<noscript>`，`#markdown-content` 初始为空                    |
| 4   | 筛选不重置     | 先搜索再点分类/标签会叠加      | 搜索时 `cat='all'` + sidebar 清高亮，三向互通                              |
| 5   | md 不实时刷新  | 改 md 页面不更新               | 运行时从相邻 `../xxx.md` 渲染，刷新即同步                                  |
| 6   | 目录混乱       | md 与 html 混放                | 静态页统一进 `html/` 子目录                                                |
| 7   | 新标签打开     | 标签链接同页跳转               | 带 url 标签渲染为 `<a target="_blank" rel="noopener noreferrer">`          |
| 8   | 首页无文章链接 | 搜索不到某些组                 | 组 `home:false` 不在首页池（资源页等二级页展示），非 bug                   |
| 9   | 弹窗层级       | 弹窗盖导航栏 / 全屏被弹窗盖住  | z-index 体系 banner30 > header29 ≥ fullscreen29 > modal28 > footer27        |
| 10  | 渲染空白       | 资源页线上主体空白             | `isLocal` 守卫误伤渲染——热重载只限本地，`generateCard()` 渲染无条件执行    |
| 11  | 回到顶部不固定 | sticky 受父容器限制滚到底停中部| `position:fixed` + bottom(首页66/二级40) + right(无目录20/有目录贴目录左) + MutationObserver 监听目录显隐 |

## 十、访问统计方案（海外站）

### 10.1 需求与选型
- 需求：**国内外访问计入同一后台** + footer 显示浏览量数字。
- 候选：GoatCounter / Umami / Plausible / Cloudflare Web Analytics。
- 结论：**Cloudflare Web Analytics**（beacon 从 Cloudflare 全球边缘加载，国内外可达、免费）+ Cloudflare Worker 代理显示 footer 数字。

### 10.2 接入（beacon）
- 启用 Web Analytics → 获 beacon（含 site token），注入 **6 根页面 + 42 静态文章页**（在 `scripts/build-articles.cjs` 模板加 beacon 后重新生成）。

### 10.3 前端显示浏览量（关键教训）
- **Cloudflare Web Analytics（RUM/beacon）数据无公开取数接口**：
  - GraphQL `rumGroups` 字段在账户 schema 不存在（报 `unknown field`）
  - REST `rum/site_info` 只做站点管理，不返回 pageViews 统计
  - → beacon 数据只能看后台，前端/第三方取不到
- **改用 `httpRequests1dGroups`（zone 级 HTTP `pageViews`）显示 footer 数字**：
  - 前置：Zone ID + 专用 API token（**Account Analytics Read + Zone Analytics Read**）+ 域名 proxied（橙云）
  - 口径：**边缘 HTTP pageViews，含爬虫、按天聚合、非实时**（比 beacon 偏大属正常）
- **Cloudflare Worker 代理**：隐藏 GraphQL token（前端直调会暴露 token），绑定自定义域 `stats.wuhuajin.com`。
- footer：`fetch('https://stats.wuhuajin.com')` 读 `total`。
- **限制**：`httpRequests1dGroups` 只能查近 **1 年**（52w1d1h），无法统计「建站以来全部」；如需建站以来累计，见 **10.6**。

### 10.4 踩坑速记
- `workers.dev` 国内超时（ERR_CONNECTION_TIMED_OUT）→ 绑定自定义域名走 Cloudflare 边缘。
- GraphQL `Authentication failed (code 9106)` → CF_API_TOKEN 填的是错误 token；需专用 API token。
- **site token ≠ API token**：beacon 的 site token 不能用于 GraphQL。
- 前端直调 GraphQL 暴露 token → 必须 Worker 代理。
- beacon 本地 CORS 报错：Cloudflare beacon 仅允许 origin http://localhost（无端口），本地 localhost:8000 不匹配被拦截；改为动态注入 + hostname 判断，本地跳过、线上正常。
- `httpRequests1dGroups` 查询范围上限 **52w1d1h**，跨年超限报 quota → 统计「建站以来全部」改 Worker + D1 自维护计数器（见 10.6）。

### 10.5 Checklist
- [ ] 启用 Web Analytics，beacon 注入全部页面
- [ ] 创建专用 API token（Account Analytics + Zone Analytics Read）
- [ ] Worker 代理查询 httpRequests1dGroups，绑定自定义域名
- [ ] footer 从 Worker 读取 total
- [ ] 确认口径（边缘 pageViews 含爬虫、非实时）可接受后再上线
- [ ] （如需建站以来全部累计）Worker + D1 自维护计数器：建库 stats-db、建表初始化、Worker 绑定 `DB`、替换代码（/hit 累加 + GET 返回）

### 10.6 建站以来全部累计（Worker + D1 自维护计数器）
- **为什么**：`httpRequests1dGroups` 只能查近 1 年（52w1d1h），无法给「建站以来全部」；更早的边缘数据 Cloudflare 不保留。
- **方案**：Cloudflare Worker + **D1**（免费 SQLite，强一致、实时）自维护计数器。
  1. 建库 `stats-db`；Console 执行建表：`CREATE TABLE IF NOT EXISTS stats(id INTEGER PRIMARY KEY CHECK(id=1), total INTEGER NOT NULL DEFAULT 0);` 并初始化：`INSERT OR IGNORE INTO stats(id,total) VALUES(1, 初始累计);`
  2. Worker → Settings → Variables → D1 binding，变量名 **`DB`**（与代码 `env.DB` 对应）。
  3. Worker 代码：`/hit`（POST）执行 `UPDATE stats SET total=total+1 WHERE id=1`；GET 返回 `{total}`；含 CORS 头；注意 **`fetch(request, env)` 签名**（漏 env 会 `ReferenceError: env is not defined` → Error 1101）。
  4. 前端全站调 `fetch('https://stats.wuhuajin.com/hit', {method:'POST'})`：footer + 5 根页 + 42 文章页 + viewer 资源页；**本地 localhost/127.0.0.1 跳过**，不污染累计。
- **口径**：每次页面加载 +1（含爬虫/刷新），从接入起累计（可用历史值初始化起点）。
- **结果**：footer 显示持续累计，不受 1 年限制，D1 持久保存。
