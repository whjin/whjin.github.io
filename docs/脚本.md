# 构建与维护脚本说明

本项目的构建、部署与维护均通过 `scripts/` 下的 Node.js 脚本完成，统一由 `package.json` 的 `npm run <name>` 调用。所有脚本**幂等**：重复执行不产生多余 diff。

## 脚本速查

| npm 命令 | 脚本文件 | 职责 |
|---|---|---|
| `npm run dev` | `scripts/build-all.cjs` + `server.js` | 全量构建一次 → 启动本地开发服务器（端口 8000）＋热重载 |
| `npm run build` | `scripts/build-all.cjs` | 全量构建所有静态页（按序执行各构建脚本） |
| `npm run build:watch` | `scripts/watch.cjs` | 文件监听 + 增量热重载 |
| `npm run build:feed` | `scripts/build-feed.cjs` | 扫描 Markdown front matter → 生成/更新 `src/template/feed/data.json` |
| `npm run build:articles` | `scripts/build-articles.cjs` | 每篇 md 预渲染为 `posts/<分类>/html/<标题>.html`；生成后清理不再对应文章的旧 html（仅限 `html/` 子目录） |
| `npm run build:home` | `scripts/build-home.cjs` | 生成首页数据 |
| `npm run build:sitemap` | `scripts/build-sitemap.cjs` | 依据 feed 自动生成 `sitemap.xml`（基础页 + 全部文章，URL 含 `/html/`） |
| `npm run build:links` | `scripts/build-links.cjs` | 构建 Link/menu 聚合页 |
| `npm run build:frontmatter` | `scripts/add-front-matter.cjs` | 为缺失 front matter 的 md 补全（title/date/category/description） |
| `node scripts/update-wordcount.js` | `scripts/update-wordcount.js` | 统计每篇文章真实字数，写回 feed 的 `wordCount` 字段 |
| `npm run clean` | `find ... -delete` | 清理 macOS 元数据文件（`._*` / `.DS_Store`），排除 `.git` |

## 常用工作流

```bash
# 本地开发（构建 + 监听 + 热重载）
npm run dev                # → http://localhost:8000

# 全量构建（部署前必跑）
npm run build

# 新增一篇文章后
npm run build:articles     # 预渲染新文章为静态 HTML
npm run build:feed         # 更新 feed 数据
node scripts/update-wordcount.js   # 更新字数
npm run build:sitemap      # 更新 sitemap

# 提交前清理 macOS 元数据
npm run clean
```

## 注意事项

- **幂等**：重跑任一构建脚本不应产生未预期的 diff；若出现，先定位重复写入逻辑。
- **build-articles 只清理自己的输出**：旧 html 清理仅作用于 `posts/<分类>/html/` 子目录，不触碰 `Link/` 菜单页等其他 html。
- **build-feed 尊重用户 description**：只要 md 里存在 `description:` 行就尊重输入、不回写覆盖；只有完全没有该行时才自动补摘要。
- **build-feed 增量同步友链数据**：按 `LINK_SECTION_MAP`（recommend/recommend1/product → 核心推荐/推荐/商品）将友链 `data.json` 增量合并到 feed。
- **徽章/埋点注入**：静态化模板（`build-articles.cjs`）会为每篇文章注入 Cloudflare beacon 等统计代码，修改后需重新构建全部文章。
